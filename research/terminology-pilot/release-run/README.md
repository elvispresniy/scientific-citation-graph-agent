# Массовый алгоритмический прогон

[Согласованный отчёт для статьи](article-report.md). Исторический [подробный отчёт расчёта](report.md) сохранён как журнал запуска, включая первоначальные диагностические сравнения. В статье результаты заголовков и аннотаций и очищенного основного текста приведены независимо. Это продолжение пилота на всех строках тех же зафиксированных релизов, а не новый случайный отбор.

Полные исходные вопросы, `question-results.md`, `query-terms.jsonl`, `excluded-questions.jsonl`, `fulltexts.jsonl`, метаданные статей, метрики по парам и кеш остаются локальными входными и промежуточными файлами. В Git опубликованы код, конфигурации, контрольные суммы, сводки и `question-metrics.jsonl` с готовыми значениями по ID вопросов. Проверка этих файлов не означает наличие полного корпуса в Git.

В `pair-metrics.jsonl` одна строка соответствует уникальной паре `question_id` + `paper_id`. Две повторные записи ID внутри исходных списков ответов не образуют дополнительных пар; исходные списки сохранены в `original_record`. Из 2 161 исходного вопроса 60 не имеют ID ответа, поэтому расчёт содержит 2 101 вопрос и 65 458 пар. Основная сводка исключает 30 вопросов настройки: 2 071 вопрос и 64 865 пар.

Правило: автоматические именные группы с определениями → различные исходные слова → осторожная словарная нормализация существительных → доля найденных слов. Расхождение равно единице минус эта доля. Выбор автоматического отбора сделан по согласованию с пилотным словарём, без независимой экспертной валидации.

## Как читать JSON

| Поле | Значение |
|---|---|
| `question_id`, `paper_id` | ID исходного вопроса и опубликованной цели; namespace сохраняется |
| `calibration_question` | Был ли вопрос в пилотных 30 вопросах |
| `metadata_identity_flag` | Название по ID отличается от названия в релизе; это флаг проверки, не доказательство неверного ID |
| `views.title_abstract` | Результат по названию и аннотации |
| `views.body_no_references` | Результат по извлечённому тексту без библиографии |
| `views.body_no_references_no_related_work` | Дополнительно исключены явно выделенные обзорные разделы |
| `status=ok` | Текст и автоматически выделенный словарь доступны; число рассчитано |
| `status=missing_text` | Нужный текст или надёжная граница раздела отсутствуют; значения равны `null` |
| `status=empty_query_vocabulary` | Правило не выделило словарь; значение не подменяется нулём |
| `word_coverage`, `word_gap` | Покрытие и расхождение слов, от 0 до 1 |
| `exact_coverage`, `phrase_coverage` | Контроль без нормализации и совпадение автоматически выделенных групп целиком |
| `content_word_coverage` | Контроль по всем содержательным словам вопроса |
| `found_words`, `missing_words` | Проверяемые исходные слова запроса, а не основы после стемминга |
| `input_sha256` | Хеш конкретных выражений запроса и использованного текста |

Для PaperPilot опорная статья хранится отдельно в `context`: её название не добавляется молча к словарю запроса. Эти числа относятся к буквальному тексту вопроса, а не ко всему информационному содержанию задачи с опорной статьёй. Отрицательные темы также остаются упомянутой лексикой; совпадение с ними не означает выполнения отрицательного требования.

HTML очищается по структуре разделов. Для PDF используются эвристические заголовки и границы; их независимая экспертная проверка в массовом прогоне не проводилась. Отсутствие явного Related Work не означает отсутствия обзора литературы во введении. Объединённый раздел вроде Introduction and Related Work удаляется целиком.

## Текущий процесс

Сбор остановлен по просьбе пользователя ограничить эксперимент объёмом ночного среза. Новых загрузок и автоматического возобновления нет. `frozen-slice.json` фиксирует состав сохранённых входных данных и их хеши. Предыдущий управляющий процесс уже работал дольше одной ночи, поэтому это срез доступных данных на момент остановки, а не точно выдержанная ночная выборка. Необработанные статьи остаются пропусками.

Правило выделения терминов сохранено для воспроизводимости: известны включение `using` и склеивание отдельных выражений. Полученные метрики предварительные; они не являются валидированной оценкой смыслового терминологического разрыва.

`driver-progress.json` и `collection-progress.json` сохраняют исторические PID остановленных процессов, итоговые счётчики и причину остановки. Лог прошлой работы находится в `cache/continuation.log`. Пропуски не превращаются в нулевое совпадение; метаданные и полнотекстовая выборка зафиксированы.

Во время сбора каждые 250 обработанных статей отчёт пересчитывался и проверялся. После остановки выполнен последний разовый пересчёт по зафиксированным входным данным. Крупные входные данные, сырые ответы источников и метрики по парам исключены из Git, но остаются в рабочем каталоге. Извлечённые тексты сохранены сжатыми; сырые HTML/PDF использовались временно.
