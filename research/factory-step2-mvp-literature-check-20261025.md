## Что существенно для нашего критерия

### Назначение ссылки: конкретное недостающее измерение

[AgentHop, Appendix C](https://arxiv.org/html/2609.34428) применяет к цепочкам
исходящих ссылок 1–2 hop каскад: Jaccard библиографий не ниже 0.08; цитатный
контекст не короче 80 символов; intent methodology/results, чисто background
исключён; затем LLM-оценка перспективности продолжения по abstracts/context
на шкале 1–5 с порогом не ниже 4. Эти пункты подтверждены субагентом в источнике.
Это описание применённого механизма; его наличие не доказывает эффект каждого
фильтра или эффективность в нашей постановке.

Наш T характеризует предварительное тематическое соответствие, G — непокрытие
словаря, M — типичность местной цитируемости. Они не отвечают на вопрос,
почему одна работа ссылается на другую. Тематичный контекст может быть фоном.

Предложение ассистента: в том же batch LLM, без отдельного вызова, извлекать
`R` для каждого сохранённого контекста: 1 — явно указано использование,
развитие, сравнение метода либо связь результатов (проверка, объяснение,
опровержение, ограничение); 0 — только фон/перечисление; null — контекста
недостаточно или назначение неясно. Дополнительно сохранить тип отношения
и src/dst. Это наша адаптация, не буквальный набор категорий AgentHop.

Для кандидата при нескольких окнах/рёбрах: R=1 при хотя бы одном явном
положительном контексте; 0 — только если все имеющиеся контексты однозначно
фоновые; иначе null. Ноль относится к просмотренным окнам (импорт сохраняет
не более двух на запись библиографии), а не к статье вообще. Не считать null
нулём и не превращать R=0 в окончательный научный отказ. При A→B контекст
принадлежит A, при B→A — B. Итоговую роль проверять по полнотексту.
В окне могут быть несколько ссылок: классифицировать отношение именно к
данному dst по сохранённому ref/bib key и позиции, не приписывать кандидату
назначение соседней ссылки. Длина окна сама по себе роли не устанавливает.

Рекомендация к следующей версии MVP: тематичность T, лексический gap G и роль
ссылки R рассмотреть как основные признаки; M сохранить диагностикой либо
отдельной экспериментальной политикой. В отличие от M, R описывает научное
отношение, ради которого исследуется переход. Это содержательное основание
рассмотреть R, не доказательство превосходства ранжирования по R. Формула
объединения T/G/R, вес и порядок применения здесь не утверждаются. Прежний
S=T*(alpha*G+(1-alpha)*M) остаётся историческим предложением, не активной
согласованной конфигурацией; заменять M на R механически также не предлагается.

### Пересечение библиографий: полезный дешёвый альтернативный признак

Для A и B: `J(A,B)=|Refs(A) intersect Refs(B)| / |Refs(A) union Refs(B)|`.
Мера не использует совпадение слов и не требует LLM, поэтому представляет
интерес при терминологическом разрыве. Это структурная общность источников,
не доказательство одной темы и не признак роли связующего узла сам по себе.

В нашем коде unarxive.references разрешает только явные arXiv ID и точные DOI.
При публикации графа INSERT INTO edges дополнительно оставляет только рёбра
с обоими концами в nodes выбранного снимка. Следовательно, J из edges — это
J по наблюдаемым локальным источникам, не по полным библиографиям.
Даже unarxive_links не восстанавливает неразрешённые библиографические записи.
Простая замена отсутствующих ссылок отсутствием научной общности недопустима.
Пустое объединение даёт неизвестное значение. При будущей реализации сохранять
область данных и полноту идентификации. Порог 0.08 и hard gate не переносить:
могут исключаться межобластные переходы с разными источниками.

Для MVP J можно оставить диагностикой/следующим сменным selector, а не вводить
новый обязательный фильтр перед уже согласованным циклом.

## Роли и цитируемость

Согласно отчёту, SciNet выбирает путь по сумме цитирований между заранее
заданными концами; AutoResearchBench выбирает цели умеренной цитируемости;
AgentHop использует зависящие от года условия затравок. Это разные функции
счётчика. Ни одна из описанных процедур не обосновывает правило «около медианы
цитирований = связующая статья» в нашем открытом наборе. Повышенная степень
также не устанавливает связи между различимыми научными направлениями.

Рекомендация: хранить профиль/тип отношения, а не выводить роль из максимального
взвешенного слагаемого. Методологический предшественник, развитие/применение
подхода, проверка/ограничение результата — предварительные типы содержательных
отношений. Научный мост требует связей с различимыми направлениями, которые
проверяются по материалу; универсальную классификацию ролей сейчас не вводить.

## Что не переносим автоматически

- Готовый запрос ScholarQuest: в нашей задаче вопрос и итоговая общность
  определяются после накопления; соответствие заранее известному запросу
  невозможно использовать как прямой критерий.
- Заранее заданные оба конца SciNet: не совпадает с нашим открытым ростом.
- Шкалы 1–5/0–2, consensus трёх судей, фиксированные года/числа references,
  пороги, 80 символов и двухшаговость: специальные настройки других конвейеров,
  без проверки не становятся нашими параметрами или научным отказом.
- Многошаговую цепочку по разным аспектам нельзя объявлять доказательством
  единой темы всей группы; финальная проверка группы остаётся отдельной.

Практически важны уже предусмотренные доступность текста, дедупликация,
явные бюджеты и остановка. Нового сложного обхода отчёт не требует.
