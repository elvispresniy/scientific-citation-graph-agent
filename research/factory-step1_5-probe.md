# Шаг 1.5: первая проба окружения затравки

Обновлено по обсуждению 24 октября 2026. Цель — предварительно оценить, стоит ли
исследовать окружение дальше, а не определить окончательную общность или запрос.

Активные модули, параметры, альтернативы и готовность всех шагов собраны
в [реестре экспериментов](factory-experiment-registry.md).

## Зафиксированные решения

- Ограничиваемся непосредственными соседями и парами «затравка — сосед».
  Соседей друг с другом на этом этапе не сравниваем.
- Для разработки промпта соседи выбираются равномерно случайно без возвращения
  из объединения входящих и исходящих связей. Используем только готовый индекс
  доступности текстов; полные тексты до выбора не читаются.
- Один ID учитывается один раз, даже при встречном цитировании. Сама затравка
  исключается. При пуле меньше бюджета берём всех; перехода на второй шаг графа нет.
- Список кандидатов сортируется по каноническому ID; фиксируются версия алгоритма,
  снимок, RNG seed, исходный отчёт шага 1, хеши пулов и выбранные пары.
- Содержательная инструкция общая для всех затравок. Окончательная тема и общность
  будущих целей не задаются. Локальные наблюдения не считаются финальной группой.
- Модели не раскрывается роль статей в графе и цель проверки перспективности.
  Она получает нейтрально обозначенные статьи A и B и оценивает их сходство.
- Терминологический счётчик пока не адаптируем и не используем для отбора.
- Отбор по контекстам цитирования остаётся перспективной альтернативой для будущего
  сравнения. Квоты направлений и ранжирование по аннотациям также пока не реализованы.

## Принятие затравки: 3 из 5

По решению пользователя бюджет пробы — до 5 соседей, для принятия нужны минимум
3 положительные пары. Предложенный ранее порог 2 из 5 заменён; это текущая
настройка первого эксперимента, а не эмпирически подтверждённый порог.

До чтения через LLM фиксируем случайный порядок соседей без возвращения и первые
пять ID. Внутри затравки проверяем последовательно только пары «затравка — сосед».
По последующему указанию пользователя увеличить параллельность активная настройка
теперь `max_concurrent_seeds=3`: три разные затравки могут оцениваться одновременно.
Конкретное стартовое значение 3 выбрано ассистентом в рамках этого указания.

Правила остановки каждой пробы:

1. После третьей положительной оценки принимаем затравку и останавливаемся.
2. Если число положительных плюс число оставшихся в этой пробе меньше трёх,
   останавливаемся без принятия. При пробе из пяти успешно обрабатываемых пар это
   происходит после третьей отрицательной оценки.
3. Не продолжаем поиск по остальным соседям до нахождения трёх положительных.
   Не требуем, чтобы положительные пары совпадали по одному общему аспекту.

Если пул меньше пяти, берём доступных, не понижаем порог три. При текущем `m=5`
на шаге 1 такой случай возможен только при изменении входов/условий доступности.
Ошибка API, некорректный JSON или недоступный текст не становятся содержательным
`false`: проверка остаётся незавершённой, выбранного соседа молча не заменяем.
При 429 новые LLM-запросы больше не допускаются и повторов нет; уже отправленные
могут завершиться, их результаты сохраняются. Технически незавершённая проверка, мешающая
определить итог, оставляет затравку незавершённой, а не отклонённой.

Активные параметры: `max_neighbors=5`, `min_positive_neighbors=3`,
`max_concurrent_seeds=3`, случайный
выбор без возвращения. Положительность пары задаёт описанный ниже бинарный промпт.
Конвейер и ранняя остановка реализованы в `factory_step1_5.py`; инструкции,
конфигурация и сменные части описаны в [FACTORY_STEP1_5.md](../code/graph_pilot/FACTORY_STEP1_5.md).
Старый набор из двух соседей на затравку остаётся отдельным материалом для разработки промпта.

## Подготовка материала для разработки промпта

Чтобы получить небольшой воспроизводимый материал, подготовлены первые 3 затравки
в сохранённом порядке шага 1 и по 2 случайных соседа с RNG seed 42, всего 6 пар.
**Эти числа относятся только к подготовке примеров для разработки промпта.**
Они не задают активную политику 3 из 5 и не позволяют проверить её целиком.
Пары не отбирались по будущей содержательной оценке или названию темы.

[Манифест пар](factory-step1_5-pilot/random-neighbors-dev-001.json).
Код: `code/graph_pilot/sample_neighbors.py`. БД открывается только для чтения.
Случайное состояние отдельное для каждой затравки, поэтому добавление других
затравок в запуск не меняет уже выбранных для неё соседей.

```sh
PYTHONPATH=code python3 -m graph_pilot.sample_neighbors \
  --db research/unarxive-pilot/graph.sqlite \
  --seed-report research/factory-step1-pilot/run-001/report.json \
  --seed-count 3 --neighbors 2 --rng-seed 42 \
  --output /tmp/step1_5-neighbors-repeat.json
```

## Содержательная оценка

Активен [промпт v2](../code/graph_pilot/prompts/step1_5-pair-v2.md);
[v1](../code/graph_pilot/prompts/step1_5-pair-v1.md) сохранён для истории run-002,
[v0](../code/graph_pilot/prompts/step1_5-pair-v0.md) — run-001.
Он сравнивает две статьи по четырём универсальным направлениям: задача/вопрос,
объекты/условия/предпосылки, подход/механизм, результаты/свойства. Краткое объяснение
опирается на содержание обеих работ и существенные различия; дословные выдержки
больше не запрашиваются и не проверяются.
Все четыре оценки и итоговый `verdict` бинарные: `true` или `false`.
`true` требует существенного сходства, обоснованного содержанием обеих статей; `false` означает,
что сходство не подтверждено, включая нехватку данных, которая поясняется текстом.
V2 по указанию пользователя смещает оценку к существенной частичной общности:
не требуется совпадения исследований целиком, способов решения, типов работ,
доменов или всех условий. Общий аспект может быть существенным модулем метода,
подзадачей или систематически разбираемым вопросом обзора. Разные ответы на один
вопрос и противоположные выводы сами по себе не отменяют сходства.
Отличия учитываются при выставлении каждого критерия; итог по инструкции равен
`problem OR method_mechanism OR results_properties`, без дополнительного
вето за различия после подтверждения критерия. Сходства только объектов и
условий недостаточно. Общая область, обычный инструмент, одинаковый датасет
или фоновая ссылка по-прежнему не являются достаточным основанием.
Правила универсальны, без названий статей и отраслевых исключений.
Это рабочая инструкция: run-003 с v2 дал 13 принятых затравок из 20 против
2 из 20 в run-002 с v1. На общих 65 парах 27 отказов стали положительными,
обратных переходов нет. Это рост допуска, а не измеренная научная точность.
Программная политика сохраняет решение модели и совместимость со старыми
ответами; отдельный запуск и сравнение сохранены в
[отчёте run-003](factory-step1_5-pilot/run-003/README.md).
Решение о потенциале затравки и её окружения принимается за пределами промпта.
Порядок ответа: `reason`, `criteria`, `differences`, последним `verdict`.
Модель должна дать краткое обоснование до выдачи итогового решения. Отдельный
reasoning, возвращённый провайдером, сохраняется в `completion.json` и удобном
`reasoning.json` как внутренняя диагностика. Дополнительного LLM-запроса нет;
отсутствие этого необязательного поля не блокирует оценку.

При подготовке исходного манифеста полные тексты и запросы LLM не использовались.
Политика 3 из 5 и сквозной исполнитель реализованы и проверены без внешней сети.
24 октября по указанию пользователя начат основной научный run-001: 20 затравок,
до 100 пар, параллельность 3, 8192 выходных токена и ожидание HTTP 300 секунд.
Подключён отдельный `step1_5-llm-run.json`; старый технический пример не заменяет
его. Статус и результаты сохраняются в `factory-step1_5-pilot/run-001/report.json`.
Прогон остановился после трёх ответов из-за буквального несовпадения текстовых
выдержек `evidence`: модель меняла пробелы/переносы, регистр и пропускала маркеры
ссылок. Научных решений по затравкам пока нет. Подробности и диагностика:
[отчёт run-001](factory-step1_5-pilot/run-001/README.md).
После обсуждения пользователь отменил буквальную проверку выдержек и попросил
сохранять reasoning и помещать обоснование перед вердиктом. Код и активный промпт
обновлены; исходный run-001 и его исторические статусы не изменяются.

Затем выполнен [run-002 с промптом v1](factory-step1_5-pilot/run-002/README.md):
все 20 проб завершены, 2 затравки приняты и 18 не приняты; 72 запроса за
29 мин 44,742 с, без технических ошибок. Приняты QUICKAR (`1807.02964`, 3 из 5)
и Blessing of dimensionality (`1801.03421`, 3 из 3 проверенных с ранней остановкой).
Reasoning и порядок «обоснование до вердикта» проверены во всех 72 ответах.
Сохранённые материалы и результаты чтения далее должны передаваться на шаг 2.
Отсутствие сигнала в ограниченной пробе не доказывает бесперспективность окружения.
