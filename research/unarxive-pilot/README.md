## Источник и граница

Официальный [unarXive open subset](https://zenodo.org/records/7752615), файл `unarXive_230324_open_subset.tar.xz`:

- размер: 4 844 918 096 байт;
- MD5 проверен против опубликованного: `4e9af00b730f1b8a680e4d7a47465395`;
- SHA-256: `bce33d7a8410af51659ee6c037b2a0796d50026f95f14dbbc9075da6b29795b1`.

Архив полностью скачан и проверен, но **импортирован не целиком**. Потоковый проход обработал 76 337 записей и остановился на лимите 30 000 подходящих CS-документов. 149 записей с пустым телом пропущены. Для рабочего графа выбран связный BFS-префикс крупнейшей доступной компоненты, затем другие компоненты до 10k вершин. Порядок и ограничения записаны в manifest базы и `run-report.json`; это подготовка технического корпуса, не исследовательский отбор затравок фабрики.

Основные рёбра получены из arXiv ID библиографий. Дополнительно сохранены 945 связей по точному DOI: значение из структурированной библиографии совпало с DOI ровно одной статьи каталога. **Все 945 связей сверены с исходными документами**; конфликтов с явными arXiv ID и несовпадений DOI не найдено. Нечёткое сопоставление названий не применялось.

Дополнительный DOI-проход остановлен по времени после 1044 секунд и не претендует на полноту. Его частичный результат сохранён. В коде для последующих сборок этот необязательный проход ограничен 60 секундами; контроль прогресса и статус полноты сохраняются. Для точного повторения текущего среза следует использовать зафиксированные экспорты узлов/рёбер, а не рассчитывать на одинаковый временной cutoff при пересборке.

88 586 извлечённых исходящих связей от выбранных статей ведут за пределы опубликованного графа. Они сохранены в промежуточном индексе и библиографиях, но не включены в локальные степени. Пустой список API — отсутствие извлечённых соседей **в данном снимке**, а не отсутствие цитирований в науке. `snapshot_list_complete` обозначает полноту сохранённых связей внутри выбранного снимка; глобальная полнота не заявляется.

## API и общий клиент

Сохранены маршруты исходного сервера pasa2:

- `/paper/{arxiv_id}`;
- `/neighbors/{arxiv_id}` с `direction`, `limit`, `offset`, `influential_only`;
- `/healthz`.

Работают оба направления, нормализация версий, старые ID со слешем и пагинация. Согласованные ограничения альтернативного источника остаются явными:

- `corpusid`, `isinfluential`, `influential_total` равны `null`;
- `influential_only=true` возвращает 422 `unsupported_feature`;
- `merged_latex=null`: структурированный текст не выдаётся за исходный LaTeX;
- полный доступный текст возвращается в `text`, формат — `unarxive_structured_text`; оригинальные `body_text`, `bib_entries`, `ref_entries` также доступны;
- `lmdb`/`papers_lmdb` в health равны `null`, фактическое хранилище — SQLite и gzip-документы.

Это совместимость маршрутов и общего клиента с явно обозначенными отличиями данных, а не полная семантическая копия S2. Экспериментальный код рекомендуется писать через `GraphClient`: его `.text()` возвращает настоящий LaTeX оригинального backend либо структурированный текст unarXive с явным `format`.

```python
from graph_pilot.client import GraphClient

graph = GraphClient('http://127.0.0.1:8765')
paper = graph.paper('1312.6199')
text = graph.text('1312.6199')
neighbors = graph.neighbors('1312.6199', 'citations', limit=50)
```

Запуск из корня, если сервер остановлен:

```sh
PYTHONPATH=code python3 -m graph_pilot --db research/unarxive-pilot/graph.sqlite serve --port 8765
```

Старый пустой S2-сервер штатно остановлен. Его SQLite-база, июньский Parquet, исходники pasa2 и замороженный лексический корпус сохранены отдельно и не изменялись.

## Проверка настоящих данных

Через HTTP и единый клиент успешно выполнен маршрут:

```text
1312.6199  --citations--> 1808.05587
1808.05587 --citations--> 1805.08522
1805.08522 --references-> 1706.10239
1706.10239 --citations--> 2105.13462
```

Прочитаны тексты всех пяти статей. Для `1312.6199` получено 28 435 символов, для остальных — от 40 459 до 74 121. Проверены соседние страницы, статус неподдерживаемого фильтра влияния, отсутствие вымышленных S2-полей, согласованность foreign keys и десять исходных рёбер непосредственно против библиографий. Все 945 добавленных DOI-связей проверены отдельно.

**17 автоматических тестов проходят**, включая совместимость исходных маршрутов, направления и фильтр S2, границы unarXive, нормализацию ID, чтение текстов, точный DOI join и запрет замены явного arXiv ID конфликтующим DOI. Новые LLM-запуски, генерация задач и сравнение поисковых методов не выполнялись.

## Ресурсы и артефакты

- потоковый импорт и первоначальная сборка: **458 секунд**, пик RSS **326 МиБ**;
- необязательный DOI-проход: 1044 секунды, пик RSS около 134 МиБ;
- SQLite: **504 905 728 байт**, около **482 МиБ**;
- сжатые тексты 30k кандидатов: **1 413 474 957 байт**, около **1,32 ГиБ**;
- весь основной локальный комплект вместе с исходным архивом: около **6,3 ГиБ** логических данных, без учёта небольших служебных файлов и накладных расходов файловой системы.

Архив и документы целиком в RAM не загружаются. Пик RSS относится к конкретному процессу, не к памяти всей системы; файловый кеш ОС учитывается отдельно.

Локальные данные игнорируются Git:

- `graph.sqlite` — каталог, граф, источники, конфигурация и статусы;
- `documents/` — структурированные gzip-документы;
- `data/` — проверенный архив, download checkpoint и точные экспорты снимка.

Небольшие отчёты доступны рядом:

- `run-report.json` — статистика, ограничения, источник и хеши кода;
- `validation.json` — проверенная HTTP-цепочка и чтение текстов;
- `import-resources.json`, `enrichment-resources.json` — фактические ресурсы.

Зафиксированные экспорты:

- узлы: `data/snapshot-nodes.jsonl`, SHA-256 `763bcbeab505cd202063805775055cc69d6a88d99104f3786769b81df8f11b02`;
- рёбра: `data/snapshot-edges.jsonl`, SHA-256 `4d836e06e2b21223384f9cec08c156534454de3ddcf809cb40eb61ca98dbbea3`.
