# unarXive: офлайн-граф и совместимые маршруты

Источник: [unarXive open subset](https://zenodo.org/records/7752615), архив `unarXive_230324_open_subset.tar.xz`, **4 844 918 096 байт**, опубликованный MD5 `4e9af00b730f1b8a680e4d7a47465395`. Полный архив не нужен для распаковки в файловую систему: импортер последовательно читает JSONL из TAR/XZ. Публикации источника заканчиваются 2022 годом; это отдельный снимок, июньские данные 2026 года не заменяются.

## Получение и сборка

Из корня репозитория, после установки зависимостей `requirements.txt`:

```sh
# Четыре HTTP Range-запроса, один файл, checkpoint, без повторов сетевых ошибок.
# У директории должен быть только наш .part от последовательной загрузки того же URL,
# либо download-state.json этого загрузчика. Для независимой загрузки нужна новая директория.
PYTHONPATH=code python3 -m graph_pilot.download_unarxive \
  --directory research/unarxive-pilot/data --seconds 1200

# Проверка MD5 обязательна для официального архива; дополнительно фиксируется SHA-256.
PYTHONPATH=code python3 -m graph_pilot --db research/unarxive-pilot/graph.sqlite import-unarxive \
  --archive research/unarxive-pilot/data/unarXive_230324_open_subset.tar.xz \
  --expected-md5 4e9af00b730f1b8a680e4d7a47465395 \
  --snapshot-id unarxive-open-cs-local-2026-10-18 \
  --max-candidates 30000 --max-nodes 10000 --max-document-mib 1536 --seconds 2400

PYTHONPATH=code python3 -m graph_pilot --db research/unarxive-pilot/graph.sqlite serve --port 8765
```

Файлы S2-пилота и лексического эксперимента остаются самостоятельными. Запуск unarXive не обращается к S2, не запускает старые сборщики и не загружает модели.

Каталог кандидатов: первые подходящие статьи с категорией `cs.*` в порядке архива, непустым телом, до 30k документов и 1536 МиБ сжатых JSON. Рост ограничивается также временем, размером промежуточной SQLite-базы 2 ГиБ и минимумом свободного диска 5 ГиБ. Структурированный оригинал каждого документа сохраняется gzip, вместе с source hash, именем TAR-member и номером строки. Остальные члены архива не извлекаются; пути из TAR не используются как пути записи.

Рёбра берутся из `bib_entries.ids.arxiv_id`, явных arXiv ID/URL библиографии и `contained_arXiv_ids`, а не из любых упоминаний ID в тексте. Версии нормализуются, дубли и самоссылки исключаются. Запись ребра сохраняет ключ библиографии, исходную ссылку и до двух окон контекста цитирования; полный документ сохраняет все исходные абзацы и маркеры.

После импорта выполняется дополнительный точный join: DOI из структурированной библиографической записи или DOI URL сопоставляется с DOI в метаданных импортированных статей. Используются только DOI, однозначные внутри каталога; неоднозначные DOI пропускаются. Нечёткое сравнение названий не применяется. В evidence сохраняется метод разрешения идентификатора, в `doi_enrichment` — количество добавленных связей.

После импорта строится индуцированный граф кандидатов. Для рабочего среза выбираются до 10k вершин: сначала самая большая слабая компонента, BFS от вершины наибольшей степени, при равенстве — по ID. Если компонента меньше лимита, добавляются следующие компоненты. Это **технический отладочный корпус**, а не репрезентативная выборка, исследовательский отбор затравок или искусственно усложнённый бенчмарк.

Полнота означает, что сохранены все извлечённые связи между выбранными вершинами. Она **не** означает полную библиографию, все цитирования в arXiv, полный unarXive или полноту S2. Граничные ссылки остаются в `unarxive_links` и исходных библиографиях. Глобальную входящую степень и D_max нельзя оценивать по этому срезу как по полному корпусу.

При остановке по бюджету публикуется явно ограниченный корпус уже сохранённых документов. `import_progress.archive_scan_complete=false` фиксирует неполный проход по архиву. Повтор сборки готового snapshot идемпотентен; для других параметров или расширения нужен новый каталог/БД. Входной архив можно использовать повторно, не скачивая его ещё раз.

## Совместимость API

Поддерживаются маршруты исходного сервера:

- `GET /paper/{arxiv_id}`;
- `GET /neighbors/{arxiv_id}?direction=references|citations&limit=50&offset=0&influential_only=false`;
- `GET /healthz`.

Нормализация версий, оба направления, пагинация, 404 для отсутствующей статьи и 422 для неверных параметров сохранены. ID со слешем поддерживаются локально через `{arxiv_id:path}`; оригинальному серверу pasa2 для старых ID нужна такая же поправка маршрута.

Общие поля `/neighbors`: `arxiv_id`, `corpusid`, `direction`, `influential_only`, `total`, `influential_total`, `offset`, `limit`, `returned`, `items`; у соседей — `arxiv_id`, `corpusid`, `title`, `year`, `isinfluential`.

Неизвестные поля не заполняются вымышленными значениями:

| Поле/функция | Поведение на unarXive |
|---|---|
| `corpusid` | `null`, локальные номера не выдаются за S2 CorpusId |
| `isinfluential`, `influential_total` | `null`, неизвестное не превращается в отрицательное |
| `influential_only=true` | 422 с `code=unsupported_feature` |
| `merged_latex` | `null`, очищенный текст не выдаётся за исходный LaTeX |
| `text`, `text_format` | Настоящий текст и `unarxive_structured_text` |
| `body_text`, `bib_entries`, `ref_entries` | Сохранённые структурированные данные источника |
| `papers_lmdb`, `lmdb` в health | `null`, фактическое хранилище обозначено отдельно |

Это совместимые маршруты с **явно согласованным расширением контракта**, а не побитовая или полная семантическая копия S2. `capabilities` сообщает поддерживаемые функции. `snapshot_list_complete=true` относится к опубликованному индуцированному срезу; `remote_list_complete` для unarXive остаётся false.

Старые вспомогательные маршруты `/paper?paper_id=...`, `/text?paper_id=...`, `/neighbors?paper_id=...` также сохранены.

## Единый клиент

```python
from graph_pilot.client import GraphClient

graph = GraphClient('http://127.0.0.1:8765')
print(graph.health())
outgoing = graph.neighbors('ID_СТАТЬИ', 'references')
article = graph.text('ID_СТАТЬИ')
print(article['format'], article['text'])
```

При переключении на исходный сервер меняется `base_url`. Клиент использует исходные маршруты и читает настоящий `merged_latex`, когда он доступен; для unarXive получает явно обозначенный структурированный текст. Код фабрики должен опираться на arXiv ID и метод `.text()`, а не требовать числовой S2 ID или считать `null` влияния значением false.

Формулы восстанавливаются из `ref_entries.latex`, маркеры цитирования сохраняются как `[cite:...]`. Это представление для локальной отладки; оно отличается от LaTeX и от старого PDF/HTML-кеша. Сравнения методов должны использовать согласованное представление текста.
