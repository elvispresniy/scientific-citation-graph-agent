# Шаг 1.5: проба окружения

Исполнитель: `factory_step1_5.py`. Активные научные решения и альтернативы:
[реестр](../../research/factory-experiment-registry.md),
[описание шага](../../research/factory-step1_5-probe.md).

## Сменные части

`probe_modules.py` содержит именованные реализации и реестры функций. Новые
алгоритмы подключаются в соответствующий реестр, без изменения цикла исполнения.
Неизвестное имя в конфигурации отклоняется; динамической загрузки чужого Python нет.

| Часть | Текущий модуль | Контракт |
|---|---|---|
| Выбор соседей | `uniform_index_v1` | `(database, seed_report, config) → план` с уникальными соседями в фиксированном порядке |
| Подготовка текста | `fulltext_preserve_v1` | `(ответ /paper, ID) → текст, формат, исходный текст, хеши и обработка` |
| Оценка пары | Отдельный файл промпта + `LLMClient` | Нейтральные статьи A/B → исходный ответ модели |
| Проверка ответа | `validate_response` | Нормальное завершение, JSON, бинарные критерии/итог и структурная согласованность; сопоставления выдержек с текстом нет |
| Решение по паре | `model_verdict_v1` | Проверенный ответ → boolean; сейчас сохраняет решение модели |
| Решение по затравке | `min_positive_v1` | Число положительных, неразрешённых и порог → `true`, `false` или технически незавершённое решение `null` |

Четыре критерия и итог модели всегда бинарны. `null` используется только для
незавершённого решения конвейера, не как оценка сходства в промпте.
Активный [промпт v2](prompts/step1_5-pair-v2.md) просит короткое содержательное
обоснование перед оценками и финальным решением: `reason → criteria → differences → verdict`.
Дословные выдержки не запрашиваются и не проверяются. В старых ответах поле
`evidence` допустимо как непрозрачная внутренняя диагностика и не влияет на решение.
Сходство только объектов не позволяет модели вернуть положительный итог.
V2 допускает частичную общность задачи, механизма или исследуемого свойства,
в том числе в существенном модуле метода или систематическом разделе обзора.
Различия учитываются отдельно для каждого критерия; итог в инструкции равен
`problem OR method_mechanism OR results_properties`, без повторного отказа
из-за отличий, которые не отменили эту общность. Точное совпадение исследований
не требуется. Именованных примеров статей и специальных правил для отраслей нет.

V1 сохранён как инструкция run-002, v0 — run-001. Программный валидатор и
`model_verdict_v1` сохраняют прежнюю совместимость с ответами старых промптов:
они проверяют обязательные поля и запрет положительного итога без основного
критерия, но не добавляют новую проверку обратной импликации. Правило OR в v2
является инструкцией модели. В
[run-003](../../research/factory-step1_5-pilot/run-003/README.md) с v2 допущены
13/20 затравок против 2/20 с v1; все 75 ответов выполнили OR-правило.
Это измерение допуска, а не подтверждение научной точности фильтра.

## Политика пробы

До LLM-чтения фиксируются до пяти непосредственных соседей из читаемых `In ∪ Out`,
без повторов и самоссылок. Последовательность отдельная для каждой затравки;
отбор наследует воспроизводимость `sample_neighbors.py`. Нет поиска «до успеха»
по остальному окружению, второго шага графа или требования общей темы всех пар.

`max_concurrent_seeds=3` в активной конфигурации разрешает одновременную оценку
трёх разных затравок. Внутри каждой выполняется только одна пара за раз, в её
зафиксированном порядке. Завершившая пробу затравка освобождает место следующей.
Загрузка текстов, обновление отчёта и кэш координируются одним потоком; HTTP-вызовы
LLM выполняются в ограниченном пуле потоков. Общие бюджеты запросов и пар не
умножаются на число работников. По умолчанию при отсутствии поля в старом конфиге
используется последовательный режим 1; значение в активном конфиге явно равно 3.

Текущий порог — три положительные пары. После третьей положительной останавливаемся
с принятием; когда положительных плюс оставшихся в пробе меньше трёх — без принятия.
При пяти обработанных парах ранний отказ возможен после третьей отрицательной.
Порог не снижается при маленьком пуле. Научный отказ означает отсутствие достаточного
сигнала в пробе, а не отсутствие полезных статей во всём окружении.

Любая техническая ошибка останавливает весь запуск без повтора и замены соседа.
Ошибки, пустой ответ, `finish_reason=length` и нарушение схемы JSON не считаются
отрицательными парами. Уже выполненные оценки сохраняются. При 429 повторов нет,
новые LLM-запросы больше не допускаются, ожидающие задания отменяются. Уже
отправленные запросы нельзя отозвать: ждём их завершения и сохраняем ответы,
не назначая этим затравкам новых соседей. Частично выполненные пробы остаются
незавершёнными, если сохранённых оценок недостаточно для решения.

## Конфигурация

[factory-step1_5-local.json](configs/factory-step1_5-local.json) содержит активный
путь: 20 затравок из текущего run-001, до 5 соседей, порог 3, RNG seed 42,
до 3 параллельно оцениваемых затравок,
имена модулей, путь промпта и локального токенизатора. Пути внутри конфигурации
разрешаются относительно самого файла. Меняйте копию конфигурации для нового опыта.

Вызов `run` требует отдельный `--llm-config`: старые smoke-лимиты автоматически
не подставляются. [step1_5-llm.example.json](configs/step1_5-llm.example.json)
— **технический пример, не согласованный научный бюджет**: 4096 выходных токенов,
temperature 0, 60 секунд, до 100 запросов, до миллиона входных символов.

Для запрошенного основного `run-001` подключён отдельный
[step1_5-llm-run.json](configs/step1_5-llm-run.json): 8192 выходных токена,
300 секунд ожидания HTTP, до 100 запросов, temperature 1.0, top_p 0.95,
reasoning_effort medium. Лимиты задаются явно; при ошибке сервера настройки
автоматически не меняются. Ответ сохраняет полное поле `message`, usage и
длительность запроса, даже если финальный текст не проходит валидацию.
Для запуска одной пары дополнительный `--max-pairs 1` ограничивает весь запуск,
даже если в LLM-конфигурации разрешено больше запросов.
Поэтому `--max-pairs 1` намеренно оставляет только одну пару и при параллельности 3.

Контекст проверяется непосредственно перед конкретным запросом по локальному
токенизатору с проверкой SHA-256. К содержимому сообщений добавляются выходной бюджет
и явный резерв на chat template (в стартовой конфигурации 2048). Это локальная
проверка, тождественность серверного токенизатора и шаблона не подтверждена.
При превышении лимита запрос не отправляется, текст не обрезается. Исследование
длин корпуса после правки очистки не повторяется.

Зависимости для исполнения: `requirements-step1_5.txt`. Файл токенизатора должен
уже существовать; автоматического скачивания, поиска моделей или пробных вызовов нет.
Секрет — только `GRAPH_LLM_API_KEY` или скрытый `--ask-key`, без записи в артефакты.

## Команды

Из корня репозитория. Все выходные пути должны быть новыми.

План: только индексы, без полнотекстов, графового HTTP API и LLM:

```sh
PYTHONPATH=code python3 -m graph_pilot.factory_step1_5 plan \
  --config code/graph_pilot/configs/factory-step1_5-local.json \
  --db research/unarxive-pilot/graph.sqlite \
  --seed-report research/factory-step1-pilot/run-001/report.json \
  --output /tmp/step1_5-plan
```

Реальный запуск одной пары (отправляет тексты на настроенный LLM-сервер):

```sh
PYTHONPATH=code python3 -m graph_pilot.factory_step1_5 run \
  --config code/graph_pilot/configs/factory-step1_5-local.json \
  --db research/unarxive-pilot/graph.sqlite \
  --seed-report research/factory-step1-pilot/run-001/report.json \
  --graph-url http://127.0.0.1:8765 \
  --llm-config code/graph_pilot/configs/step1_5-llm.example.json \
  --max-pairs 1 --ask-key \
  --output /tmp/step1_5-one-pair
```

Сначала проверяется `/healthz`. Если API сообщает снимок, он обязан совпасть
с планом; у исходного API без `snapshot_id` отсутствие проверки явно фиксируется.
Никакой искусственный корпус или S2-поле не подставляются.

Для полной пробы уберите ограничение `--max-pairs 1` после выбора LLM-бюджета.
Прерывание Ctrl-C сохраняет выполненную часть. Автоматическое продолжение
прерванного запуска пока не реализовано; существующий каталог не перезаписывается.

Пересчёт другого порога без LLM и без изменения исходного запуска:

```sh
PYTHONPATH=code python3 -m graph_pilot.factory_step1_5 reaggregate \
  --run /tmp/step1_5-one-pair --threshold 2 \
  --output /tmp/step1_5-threshold-2.json
```

После ранней остановки данных для нового порога может не хватить — тогда будет
`accepted: null`, а не выдуманная отрицательная оценка. Изменение порога не меняет
саму выборку соседей или результаты LLM. Новый промпт требует нового оценивания.

## Артефакты

- `plan.json`, `prompt.md` — точный порядок, конфигурация, версия кода, промпт и хеши.
- `report.json` — атомарный checkpoint после каждой стадии; принятые затравки,
  оценки, ошибки, бюджеты и причины остановки. Готовые оценки передаются на шаг 2.
  Порядок затравок и соседей фиксирован планом; межзатравочный порядок завершения
  и номера фактически начатых пар зависят от времени ответов и сохраняются в отчёте.
- `papers/*.json.gz` — исходные и подготовленные тексты с хешами и происхождением.
  Статья запрашивается у API один раз на запуск; повторное чтение идёт с диска,
  полный набор текстов не удерживается в оперативной памяти.
- `pairs/NNNNNN/input.json.gz` — точные сообщения до запроса, без служебных ролей графа.
- `pairs/NNNNNN/completion.json` — исходный ответ, модель, usage и причина завершения
  до проверки содержимого, включая некорректные ответы.
- `pairs/NNNNNN/reasoning.json` — отдельная внутренняя диагностика полей `reasoning`
  и/или `reasoning_content`, если провайдер их вернул. Сохраняется до проверки
  финального JSON. Если полей нет, пишется `available: false`, оценка не блокируется.
- `pairs/NNNNNN/result.json` — проверенная оценка и отдельное решение политики пары
  либо техническая ошибка.

Reasoning, обоснование и прежние выдержки — внутренние артефакты отладки.
Политика пары использует `verdict`, а политика затравки — число положительных
пар. Дополнительного LLM-запроса для reasoning нет. Сохранение полей провайдера
не означает, что сервер обязан их возвращать или что их содержание доказывает
корректность оценки. Исторические результаты run-001 не переписываются.

Проверки без внешней сети:

```sh
PYTHONPATH=code python3 -m pytest code/graph_pilot/tests/test_factory_step1_5.py \
  code/graph_pilot/tests/test_llm.py -q
```
