# Шаг 1 фабрики: локальный отбор затравок

Реализация согласованного [алгоритма](../../research/factory-step1-region-mining.md)
в режиме одинаковых весов: `factory_step1.py`. Работает по готовому снимку SQLite,
не скачивает данные, не читает полнотексты и не вызывает модели.

Из корня репозитория:

```sh
PYTHONPATH=code python3 -m graph_pilot \
  --db research/unarxive-pilot/graph.sqlite factory-step1 \
  --config code/graph_pilot/configs/factory-step1-local.json \
  --output research/factory-step1-pilot/run-001
```

Выходной каталог должен быть новым. Повторный запуск с той же конфигурацией в другой
каталог воспроизводит выбранные ID и порядок. Старые результаты не перезаписываются.
База открывается через SQLite `mode=ro`, все входы читаются в одной транзакции.
Команда не меняет технические `nodes.seed` и настройку `seeds` сборщика S2.

## Конфигурация

Все поля задаются явно в JSON; неизвестные поля и неправильные типы отклоняются.

| Поле | Значение первого запуска | Ограничение |
|---|---:|---|
| `snapshot_id` | `unarxive-open-cs-local-2026-10-18` | Должен совпасть с БД |
| `K` | 20 | Целое ≥ 1 |
| `m` | 5 | Целое ≥ 1 |
| `D_max` | 50 | Целое ≥ 0 |
| `rng_seed` | 42 | Целое |
| `weight_mode` | `uniform` | Все веса равны 1; других режимов пока нет |

Список вершин — таблица `nodes`, а не весь каталог `papers`. Степени считаются по
корректным уникальным рёбрам между вершинами этого снимка. Самоссылки, внешние и
некорректно сопоставленные связи исключаются с отдельными счётчиками.

Статья пригодна при каноническом ID, наличии корректного объекта метаданных и
статуса `available` хотя бы у одного источника текста. Проверка содержимого текста
не входит в этот шаг. Сосед считается читаемым по тому же индексу доступности.
Объединение входящих и исходящих соседей устраняет повтор при встречном цитировании.
Входящая степень учитывает и соседей без текстов.

Допуск: пригодность, минимум `m` читаемых соседей и входящая степень ≤ `D_max`.
Минимума входящей степени нет. Статья, не прошедшая допуск, остаётся в графе и может
учитываться как сосед. Ограничений на компоненты, годы и предметные области нет.
При пустом пуле результат пустой; ограничения автоматически не ослабляются.

Площадки и треки в этом режиме не обогащаются: значения неизвестны, вес всегда 1.
Поддержка повышающих коэффициентов не реализована.

Доступно отдельное [ядро Gumbel-Top-k на C++/OpenMP](../gumbel_topk/README.md):
добавьте `--sampler gumbel-native --threads 4` к команде выше. Оно использует тот же
расчёт допуска, но другой RNG: распределение выборки сохраняется в идеальной
модели, исторические выбранные ID не воспроизводятся. По умолчанию остаётся
исходный последовательный режим. Подготовка графовых метрик не распараллелена.

## Выборка и воспроизводимость

Допущенные ID сортируются по возрастанию. На каждом шаге `random.Random(rng_seed)`
выбирает равновероятный индекс через `randrange`; статья извлекается из оставшегося
списка. Это последовательная выборка без возвращения с одинаковыми весами.

Сохраняются версия алгоритма, версия Python, SHA-256 исходника, конфигурация,
хеши списка вершин, уникальных рёбер, доступности текстов, метаданных и метрик допуска.
Одинаковая конфигурация требует также одинаковых входов и реализации RNG.
Время выполнения и путь к БД не обязаны совпадать при повторном запуске.

Артефакты:

- `config.json` — точная конфигурация запуска;
- `candidates.jsonl` — метрики, вес и все причины отказа для каждой вершины;
- `selected.jsonl` — выбранные статьи в порядке извлечения;
- `report.json` — статистика, конфигурация, контрольные суммы и выбранные статьи.

Реализация для локальной отладки хранит множества входящих и исходящих соседей
в памяти: O(V + E), выборка — O(K·V) из-за удаления из списка. Она не предназначена
для загрузки многомиллиардного графа в память; на кластере подготовка метрик может
работать по отдельным индексам с тем же контрактом результата.

Дальнейшая работа со статьями использует общий `GraphClient` и исходные маршруты
`/paper/{arxiv_id}`, `/neighbors/{arxiv_id}`. Массовый расчёт шага 1 использует
локальные индексы напрямую, чтобы не выполнять тысячи HTTP-запросов. Для другого
хранилища понадобится адаптер индексов. Общий API графа не меняется.
