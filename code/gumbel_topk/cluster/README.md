# Запуски на Ломоносове-2

Перед использованием прочитать `research/lomonosov2-access/README.md` и сохранённые
правила. Скрипты используют штатную обёртку `run`, один узел `test`, 14 CPU-ядер,
лимит 14 минут. Вычисления на узле доступа не выполнять.

GCC загружается в submit.sh на узле доступа и передаётся заданию через
`--export=ALL`. Повторная загрузка Lmod на вычислительном узле не выполняется:
первый smoke 15 ноября выявил там отсутствие Lua-модуля posix. Runner проверяет
версию унаследованного GCC и сохраняет фактические зависимости бинарника (`ldd`).

Скопировать исходники, Makefile, benchmark.py и cluster/ в отдельный каталог
в `~/_scratch`. Собирать Linux-бинарный файл на кластере; macOS-бинарник не подходит.
Сборка разрешена на узле доступа:

```sh
module add gcc/12.3.0 slurm
cd ~/_scratch/gumbel-topk-YYYYMMDD
mkdir -p build
printf '%s\n' 'make CXX=g++ all serial; GCC module gcc/12.3.0; default Makefile flags' > build/build-command.txt
make CXX=g++ all serial > build/build.log 2>&1
chmod u+x cluster/run_matrix.sh cluster/submit.sh
bash cluster/submit.sh smoke 1000000
```

После успешной проверки:

```sh
bash cluster/submit.sh full 100000
bash cluster/submit.sh full 1000000
bash cluster/submit.sh full 10000000
# Следующий запуск — после освобождения места в очереди, не более трёх задач.
bash cluster/submit.sh full 100000000 20
bash cluster/submit.sh full 100000000 1000
bash cluster/submit.sh full 100000000 10000
```

Не ставить все задания поверх незавершённых запусков: для `test` документация
указывает максимум три задания пользователя, из них одно работающее. Текущую
очередь проверять `squeue -u "$USER"`.

Размер 100 млн разделён по K на три задания: smoke на целевом узле показал
около 0,09–0,10 с для N=1 млн в один поток; экстраполяция полной группы на
100 млн с прогревом, повторами и генерацией даёт риск превышения 14 минут.
Это инженерная оценка, не измеренное время большого запуска. Состав матрицы
не меняется. Третий аргумент submit.sh задаёт один K вместо всех трёх.

Для контролируемой постановки шести заданий можно запускать на узле доступа
`module add slurm; python3 cluster/fill_queue.py`. Один вызов заполняет до
трёх мест в очереди и завершается; повторный вызов после освобождения мест
учитывает сохранённый submission-state.json. Не запускать несколько экземпляров
этого диспетчера одновременно и не удалять его состояние между вызовами.

Полная матрица: N ∈ {100000, 1000000, 10000000, 100000000}, K ∈ {20, 1000, 10000},
веса uniform / skewed, P ∈ {1, 2, 4, 8, 14}, seed=42. Для каждой конфигурации
один прогрев и семь измерений; в smoke — K=20/1000 и три измерения. Для каждого
N/K/весов результат каждого P должен побитово совпадать с P=1. Ускорение считается
отдельно внутри каждой такой группы. Синтетика моделирует вход ядра, не рёбра
графа и не научное содержание статей.

На входной массив для N=100 млн требуется 1,6 ГБ (100 млн × 16 байт), плюс
кучи, результаты и среда исполнения. Вход генерируется в RAM и не сохраняется
как большой файл. Время генерации и запуска процесса исключено из времени ядра,
но включено в process_seconds. Отдельные JSON сохраняют все повторы и выбранные
ID/score; общий report.json создаётся только после завершения всей задачи.

Для воспроизводимости сохраняются исходники, их хеш в бинарном файле, команда
сборки, версии компилятора/OpenMP/Python, хеш бинарника, аппаратная конфигурация,
номер задания, привязка потоков, сырые времена. Физическая RAM берётся из
`/proc/meminfo` внутри выделенного вычислительного узла, не из поля памяти sinfo.

После завершения скопировать results/ в постоянное хранилище и локально.
Scratch может очищаться; не использовать его как единственную копию результатов.

Локально объединить четыре завершённых `full`-отчёта и построить графики:

```sh
python3 code/gumbel_topk/summarize.py \
  --reports results/full-n100000-job*/report.json \
            results/full-n1000000-job*/report.json \
            results/full-n10000000-job*/report.json \
            results/full-n100000000-k*-job*/report.json \
  --output research/factory-step1-pilot/lomonosov2-summary-001
```

Нужен локальный matplotlib. Проверяются полнота матрицы, отсутствие дубликатов,
идентичность выбранных ID/score и правильность базы ускорения. Неполная матрица
не достраивается предположениями. Итог: summary.md, sources.json с хешами
исходных отчётов и графики strong-scaling.png / .svg.
